# Smartwatch Vitals — Backend + Emulator

โปรเจกต์นี้มี 3 ส่วน:

1. **server/** — Backend (Node.js + Express) รับค่า Vital Signs แล้วเก็บไว้ (ไฟล์ `server/data.json` จะถูกสร้างอัตโนมัติตอนรันครั้งแรก)
2. **public/emulator.html** — หน้าจำลองนาฬิกา (Smartwatch Emulator) มีทั้งโหมด "ส่งค่าเอง" และ "ส่งอัตโนมัติตามรอบเวลา"
3. **public/dashboard.html** — หน้าง่ายๆ ให้หมอดูค่าล่าสุดของคนไข้แต่ละคน (ใช้เทสว่า emulator ส่งเข้ามาจริง)

## วิธีรัน

```bash
cd server
npm install
npm start
```

จะเห็นข้อความว่า server รันที่ `http://localhost:3000`

จากนั้นเปิดเบราว์เซอร์:

- นาฬิกาจำลอง: **http://localhost:3000/emulator.html**
- หน้าหมอ: **http://localhost:3000/dashboard.html**

เปิดสองแท็บพร้อมกันได้เลย ลองส่งค่าจากหน้า emulator แล้วดูว่าหน้า dashboard อัปเดตไหม (รีเฟรชอัตโนมัติทุก 5 วิ)

## หลักการทำงาน (สำคัญ ต้องเข้าใจตอนอธิบาย/นำเสนอโปรเจกต์)

ในของจริง นาฬิกาจะซิงค์ข้อมูลผ่าน Bluetooth ไปแอปมือถือ แล้วแอปมือถือค่อยส่งขึ้นเซิร์ฟเวอร์ผ่าน HTTP API
เนื่องจากไม่มีนาฬิกาจริง เราเลยตัด "ตัวนาฬิกา" ออก แล้วเขียนหน้าเว็บ (`emulator.html`) ให้ทำหน้าที่แทน คือ
สร้างค่า Vital Signs (ด้วยมือ หรือสุ่มแบบ auto) แล้วยิง `POST` เข้า endpoint เดียวกับที่แอปมือถือของจริงจะยิง
(`/api/vitals`) — ฝั่ง backend แยกไม่ออกว่าค่าที่ได้รับมาจากนาฬิกาจริงหรือจาก emulator เพราะหน้าตา request เหมือนกันทุกอย่าง

พอถึงเวลามีนาฬิกาจริง สิ่งที่ต้องเปลี่ยนคือแค่ "ตัวส่ง" (จากหน้าเว็บ emulator กลายเป็นแอปมือถือที่อ่านค่าจาก Bluetooth SDK ของนาฬิกา)
โดย backend และ API endpoint ไม่ต้องแก้อะไรเลย

## Endpoints ที่มี

| Method | Path | คำอธิบาย |
|---|---|---|
| POST | `/api/vitals` | รับค่า Vital Signs 1 ชุด (จาก emulator หรือนาฬิกาจริง) |
| GET | `/api/vitals` | ดูข้อมูลทั้งหมด (ล่าสุดก่อน) |
| GET | `/api/vitals/:patientId` | ดูประวัติของคนไข้รายเดียว |
| GET | `/api/patients/latest` | ดูค่าล่าสุดของคนไข้ทุกคน (ใช้ในหน้าหมอ) |

Body ของ POST `/api/vitals`:
```json
{
  "patientId": "patient001",
  "patientName": "สมชาย ใจดี",
  "heartRate": 78,
  "systolic": 120,
  "diastolic": 80,
  "spo2": 98,
  "temperature": 36.8
}
```

## ปรับให้ตรงกับที่โจทย์ต้องการ (บันทึกทุก 4 ชม. + ปรับเวลาได้)

ในหน้า `emulator.html` ตัวเลือก "รอบเวลา" มีให้เลือกทุก 4 ชั่วโมงเป็นค่าเริ่มต้นอยู่แล้ว (ตรงกับโจทย์)
และเลือก "กำหนดเอง (นาที)" เพื่อปรับเป็นค่าอื่นได้ตามต้องการ — ใช้ตัวเลือกที่สั้น (5 วิ / 10 วิ) เวลาทดสอบ
เพื่อไม่ต้องรอ 4 ชั่วโมงจริงๆ ตอน demo

## ต่อยอด (ถ้ามีเวลา)

- เปลี่ยนจากเก็บไฟล์ JSON เป็นฐานข้อมูลจริง (เช่น MongoDB / PostgreSQL) เมื่อจะขึ้น production
- เพิ่ม authentication (คนไข้ล็อกอินด้วยบัญชีตัวเอง ไม่ใช่กรอก patientId มือ)
- เพิ่ม endpoint แจ้งเตือนหมอเมื่อค่าผิดปกติ (เช่น ส่ง LINE Notify หรือ email เมื่อ SpO2 ต่ำเกินไป)
